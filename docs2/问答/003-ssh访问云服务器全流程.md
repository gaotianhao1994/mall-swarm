# Q003：SSH 访问云服务器 — 全流程解析

> **背景**: 你配置了 `tengxun-server9` 但从 Trae IDE 中 SSH 连接不成功。
> **目标**: 搞清楚 SSH 连接到底需要哪些要素，每个要素不满足时会发生什么。

---

## 一、SSH 连接的本质

### 是什么？

SSH（Secure Shell）= 一台计算机**远程登录**到另一台计算机的加密协议。

```
你的电脑 (SSH 客户端)  ──加密通道──▶  云服务器 (SSH 服务端)
     Windows                          Linux
     Trae IDE 终端                     root@106.53.132.192
```

### 为什么需要 SSH？

| 方式 | 场景 | 问题 |
|------|------|------|
| **物理到场** | 去机房插键盘显示器 | 你的云服务器在广州/杭州，你人在电脑前 |
| **VNC 控制台** | 云厂商网页版远程桌面 | 卡顿、功能受限、不能复制粘贴 |
| **SSH** | 命令行远程操作 | ✅ 快速、稳定、可脚本化 |

## 二、SSH 连接成功的 5 个必要要素

一个 SSH 连接要成功，必须同时满足以下 **5 个条件**：

```
┌─────────────────────────────────────────────────────────────┐
│                  SSH 连接成功的 5 大要素                      │
│                                                             │
│   ① 网络能通        → 能找到服务器                            │
│   ② SSH 服务在跑    → 服务器开着门                           │
│   ③ 用户存在        → 有账号可以登录                         │
│   ④ 认证通过        → 证明你是合法用户                       │
│   ⑤ 权限允许        → 密钥文件可以被读取                     │
│                                                             │
│   缺任何一个 → ❌ 连接失败                                   │
└─────────────────────────────────────────────────────────────┘
```

### 要素 ①：网络可达 — "我能找到你家吗？"

**你需要知道什么**: 服务器的 IP 地址 + SSH 端口

```bash
# 最基本的 SSH 命令（只用了这 2 个信息）
ssh root@106.53.132.192
#    ^      ^
#    |      └── IP 地址：服务器的"门牌号"
#    └── 用户名：以谁的身份登录
#
# 默认端口是 22，如果改过就要指定：
ssh -p 2222 root@106.53.132.192
```

**验证方法**:

```bash
# 测试网络是否通（ICMP 层）
ping 106.53.132.192

# 测试 SSH 端口是否开放（TCP 层）
# Windows PowerShell:
Test-NetConnection -ComputerName 106.53.132.192 -Port 22

# 或者用 telnet:
telnet 106.53.132.192 22
```

| 结果 | 含义 |
|------|------|
| `ping 通了` / `TcpTestSucceeded : True` | ✅ 网络层没问题 |
| `Request timed out` / `TcpTestSucceeded : False` | ❌ 服务器没开机 / 安全组没开 22 端口 / 防火墙拦截 |

**常见失败原因**:
- 安全组（云厂商防火墙）没有放行 **22 端口**
- 服务器关机了
- IP 地址写错了

---

### 要素 ②：SSH 服务端在运行 — "你家开门了吗？"

**你需要知道什么**: 服务器上必须运行着 `sshd`（SSH Daemon）进程

```bash
# 登录服务器后检查（如果能登的话）
systemctl status sshd          # Ubuntu 24.04 可能叫 ssh
# 或
ps aux | grep sshd             # 看 sshd 进程是否存在
```

| 状态 | 含义 |
|------|------|
| `active (running)` | ✅ SSH 服务正常运行 |
| `inactive (dead)` | ❌ SSH 服务没启动 → `sudo systemctl start ssh` |
| `failed` | ❌ 配置有误，需要检查 `/etc/ssh/sshd_config` |

**腾讯云新机器默认情况**:
- 默认用户 `ubuntu` → SSH 服务**已开启** ✅
- 默认用户 `root` → 可能被**禁止 SSH 登录**（`PermitRootLogin no`）⚠️

这就是为什么我们之前要在新服务器上执行：
```bash
sudo sed -i 's/^#*PermitRootLogin.*/PermitRootLogin yes/' /etc/ssh/sshd_config
sudo systemctl restart ssh
```

---

### 要素 ③：用户存在 — "这个人住在这里吗？"

**你需要知道什么**: 你要用哪个用户名登录？

```bash
# SSH 命令中的 user@ip 格式
ssh root@106.53.132.192
#    ^^^^
#    这个就是用户名！
```

**每台云服务器默认的用户名不一样**：

| 云厂商 | 默认用户 | 说明 |
|--------|---------|------|
| 腾讯云（新购） | `ubuntu` | root 默认禁止密码登录 |
| 腾讯云（老镜像） | `root` 或 `ubuntu` | 取决于系统镜像 |
| 阿里云 | `root` | 通常直接给 root |

**怎么确认有哪些用户？**

```bash
# 先用默认用户登录后查看
cat /etc/passwd | grep -E "bash$|sh$" | grep -v nologin
# 输出示例:
#   root:x:0:0:root:/root:/bin/bash
#   ubuntu:x:1000:1000:Ubuntu:/home/ubuntu:/bin/bash
```

**常见错误**：
- 用 `root@IP` 登录但服务器禁止 root 登录 → `Permission denied (publickey)`
- 用 `ubuntu@IP` 但输成了 `root@IP` → 同上

---

### 要素 ④：认证通过 — "你能证明身份吗？"（最关键！）

这是 **90% 的 SSH 连接失败发生的地方**。SSH 支持两种认证方式：

#### 方式 A：密码认证

```
你的电脑: ssh root@106.53.132.192
           ↓
云服务器: "请输入密码"
你的电脑: Mall@2026_root  ← 你手动输入
云服务器: "密码正确，欢迎！" ✅
         "密码错误，滚！"    ❌
```

**前提条件**：
1. 服务器端 `sshd_config` 开启了 `PasswordAuthentication yes`
2. 该用户设置了密码（`sudo passwd root`）

#### 方式 B：密钥认证（推荐，更安全）

```
你的电脑                    云服务器
┌──────────────┐            ┌──────────────┐
│              │            │              │
│  私钥文件     │            │  公钥文件     │
│  id_rsa      │   配对验证  │ authorized_  │
│  .pem 文件   │ ◄────────► │ keys         │
│  (你保管好!)  │   数学签名  │ (存放在服务器)│
│              │            │              │
└──────────────┘            └──────────────┘
```

**工作原理（第一性原理追问）**：

> 为什么密钥比密码安全？
>
> **密码 = "你知道的信息"** → 可以被猜到、被钓鱼、被键盘记录器截获
> **密钥 = "你拥有的东西"** → 私钥永远不出你的电脑，即使中间人截获通信也无法伪造签名

**密钥认证流程**：

```
步骤1: 你生成一对密钥（公钥 + 私钥）
       公钥 = 锁（可以公开分发）
       私钥 = 钥匙（必须自己保管）

步骤2: 把公钥放到服务器的 ~/.ssh/authorized_keys 文件里
       （相当于：把锁装在门上）

步骤3: SSH 连接时
       服务器 → 发送一个随机挑战字符串
       你的电脑 → 用私钥对这个字符串签名 → 发回签名
       服务器 → 用公钥验证签名 → 匹配则放行
```

**两种密钥格式**：

| 类型 | 文件格式 | 来源 | 典型用途 |
|------|---------|------|---------|
| **RSA/ED25519 自建密钥** | `id_rsa` / `id_ed25519` | 自己 `ssh-keygen` 生成 | 阿里云 / 自建服务器 |
| **PEM 密钥** | `xxx.pem` | 云厂商控制台下载 | **腾讯云默认方式** |

---

### 要素 ⑤：密钥文件权限正确 — "钥匙能用吗？"

**这是最容易踩坑的地方！尤其是 Windows 上。**

SSH 对私钥文件的权限要求极其严格：

| 操作系统 | 要求 | 原因 |
|---------|------|------|
| **Linux/macOS** | 权限必须是 `600`（仅所有者可读写） | SSH 会拒绝读取权限过宽的文件 |
| **Windows** | 当前用户必须有**独占读取权限** | SSH 客户端会拒绝加载其他用户可读的文件 |

**Linux 上**：
```bash
chmod 600 ~/.ssh/id_rsa
chmod 600 ~/.ssh/tengxun_server9.pem
ls -la ~/.ssh/
# -rw-------  ← 开头必须是这个（600权限）
```

**Windows 上**：
```powershell
# 查看当前权限
icacls C:\Users\Administrator\Downloads\tengxun_server9.pem

# 设置为仅当前用户可读
icacls C:\Users\Administrator\Downloads\tengxun_server9.pem /inheritance:r /grant:r "Administrator:R"
```

**权限不对时 SSH 的表现**：
```
debug1: identity file C:\...\tengxun_server9.pem type -1
                                                              ^^^
                                                        type -1 = 加载失败！
```

## 四、SSH Config 文件详解

你的 `~/.ssh/config` 就是 SSH 的"电话簿"，让你用别名代替长命令。

### 当前配置逐行解读

```
Host tengxun-server9          ← 别名：以后输入 ssh tengxun-server9 就够了
    HostName 106.53.132.192   ← 实际连接的服务器 IP（门牌号）
    User root                 ← 登录用户名（以谁的身份进门）
    Port 22                   ← SSH 端口（进哪个门，默认 22）
    IdentityFile C:\Users\...  ← 私钥文件路径（你的钥匙在哪）
               \Downloads\tengxun_server9.pem
```

### Config 文件匹配规则

SSH 按**从上到下**的顺序匹配第一个符合条件的 Host：

```bash
# 你输入: ssh tengxun-server9
# SSH 做的事:
#   1. 读第1行 Host aliyun-server    → "tengxun-server9" 不匹配 "aliyun-server" → 跳过
#   2. 读第7行 Host tengxun-server   → "tengxun-server9" 不匹配 "tengxun-server" → 跳过
#   3. 读第13行 Host tengxun-server9 → "tengxun-server9" 匹配! → 使用此配置 ✅
```

**可以用通配符**：
```
Host tencent-*               # 匹配所有 tencent- 开头的别名
    User root
    IdentityFile ~/.ssh/id_rsa
```

## 五、故障排查 — 从报错信息定位问题

### 5.1 常见报错 → 原因 → 解决方案

| 报错信息 | 失败在哪个要素 | 原因 | 解决方案 |
|---------|-------------|------|---------|
| `Connection timed out` | ① 网络不通 | 安全组没开 22 端口 / 服务器关机 | 云控制台检查安全组 |
| `Connection refused` | ② SSH 服务没开 | sshd 没运行 / 端口不是 22 | `sudo systemctl start ssh` |
| `Permission denied (publickey)` | ④ 认证失败 | 公钥没放对 / 私钥不对 / 用户名错 | 检查 authorized_keys 和私钥 |
| `Permission denied (publickey,password)` | ④ 全部认证失败 | 密钥和密码都不对 | 重置密码或重新部署公钥 |
| `identity file ... type -1` | ⑤ 密钥文件无法读取 | 文件权限不对 / 路径不存在 / 格式错误 | 检查文件路径和权限 |

### 5.2 排查神器：`ssh -v`（verbose 模式）

```bash
# 加 -v 可以看到完整的连接过程日志
ssh -v tengxun-server9
```

关键日志节点对照：

```
debug1: Reading configuration data /c/Users/Administrator/.ssh/config
debug1: Matching config block: tengxun-server9          ← ✅ config 匹配成功
debug1: Connecting to 106.53.132.192 [106.53.132.192] port 22.
                                                ↑
debug1: Connection established.                        ← ✅ 要素①②: TCP连接成功
debug1: Remote protocol version 2.0                    ← ✅ SSH协议协商成功
debug1: identity file C:\...\pem type -1               ← ❌ 要素⑤: 密钥文件加载失败!
debug1: Trying private key                              ← 正在尝试用密钥认证
debug1: Authentications that can continue: publickey,password
debug1: No more authentication methods                  ← ❌ 要素④: 所有认证都失败了
Permission denied (publickey,password).                 ← 最终结果: 被拒
```

### 5.3 你的 `tengxun-server9` 连接问题诊断

根据之前的测试结果，你的问题是 **`type -1`（密钥文件加载失败）**：

```
debug1: identity file C:\Users\Administrator\.ssh\tengxun_server9.pem type -1
```

**原因分析链路**：

```
config 写的是: IdentityFile ~/.ssh/tengxun_server9.pem
                                    ↑
                              Windows 上 ~ 可能没展开正确

实际文件位置: C:\Users\Administrator\Downloads\tengxun_server9.pem
                                    ↑
                              文件在 Downloads 下，不在 .ssh 下

之前 Copy-Item 把文件复制到了 .ssh 目录，
但 IDE 沙箱限制了对该路径的操作，
导致权限可能不正确
```

**解决方案（已在 config 中改为绝对路径）**：

```
IdentityFile C:\Users\Administrator\Downloads\tengxun_server9.pem
              ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
              用完整绝对路径，避免 ~ 展开问题
```

**验证是否修复**：

```bash
# 方式1: 用完整命令测试（绕过 config）
ssh -i "C:\Users\Administrator\Downloads\tengxun_server9.pem" root@106.53.132.192 "whoami"

# 方式2: 用 config 别名测试
ssh tengxun-server9 "whoami"

# 方式3: 如果还不行，看详细日志
ssh -vvv tengxun-server9 "whoami"
# 找 identity file 那一行，看 type 是 -1 还是 1/2
```

## 六、三种连接方式对比

| 方式 | 命令示例 | 适用场景 | 安全性 |
|------|---------|---------|--------|
| **密码登录** | `ssh root@IP` 然后输密码 | 临时使用 / 救急 | 低（密码可被暴力破解） |
| **密钥登录（自建 RSA）** | `ssh -i id_rsa user@IP` | 阿里云 / 自建服务器 | 高 |
| **密钥登录（PEM）** | `ssh -i xxx.pem user@IP` | **腾讯云标准方式** | 高 |

### 我们 3 台服务器的连接方式汇总

| 别名 | IP | 认证方式 | 密钥文件 | 状态 |
|------|-----|---------|---------|------|
| `aliyun-server` | 8.134.65.121 | RSA 密钥 | `~/.ssh/id_rsa` | ✅ 可用 |
| `tengxun-server` | 106.53.106.41 | RSA 密钥 | `~/.ssh/id_rsa` | ✅ 可用 |
| `tengxun-server9` | 106.53.132.192 | **PEM 密钥** | `C:\...\Downloads\tengxun_server9.pem` | ⚠️ 待验证 |

## 七、SSH 连接检查清单（Connect 时逐项勾选）

当你发现 SSH 连不上时，按这个顺序排查：

```
□ 1. 能 ping 通吗？
     ping 106.53.132.192

□ 2. 22 端口开放吗？
     telnet 106.53.132.192 22  (或 Test-NetConnection)

□ 3. config 文件写对了吗？
     cat ~/.ssh/config  (检查 Host/HostName/User/Port/IdentityFile)

□ 4. 密钥文件存在吗？
     ls -la 密钥文件路径  (Windows: dir 密钥文件路径)

□ 5. 密钥文件权限对吗？
     (Linux: chmod 600)
     (Windows: icacls 设置仅当前用户可读)

□ 6. 服务器的 authorized_keys 里有你的公钥吗？
     ssh 到服务器后: cat ~/.ssh/authorized_keys

□ 7. 用户名对吗？（root vs ubuntu）
     云厂商不同，默认用户可能不同

□ 8. PermitRootLogin 开启了吗？（如果是用 root 登录）
     ssh 到服务器后: grep PermitRootLogin /etc/ssh/sshd_config

□ 9. 用 ssh -v 看日志定位具体卡在哪一步
     ssh -v 别名
```

## 一句话总结

> **SSH 连接 = 找到门（IP:端口）+ 门开着（sshd运行）+ 有住户（用户存在）+ 有钥匙（密钥/密码）+ 钥匙能用（权限正确）。五缺一不可。**
