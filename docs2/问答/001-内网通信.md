# Q001：什么叫做内网通信？

## 知识点：内网通信（Internal Network Communication）

### 是什么？

**内网通信** = 服务器之间通过**私有 IP 地址**互相访问，而不是通过公网 IP。

在我们的三台服务器架构中，plan.md 写的"内网通信"指的就是：

```
① 网关服务器的 Gateway 容器
    ↓ （调用）
② 数据服务器的 MySQL 容器   ← 走的是内网，不是公网
```

### 为什么用内网而不用公网？

**原因 1：安全**

| 对比 | 公网通信 | 内网通信 |
|------|---------|---------|
| 数据路径 | 用户 → 公网互联网 → 目标服务器 | 服务器 A → 云厂商内网 → 服务器 B |
| 暴露面 | 数据经过公共网络，可被截获/扫描 | 数据只在云机房内部流转，外部无法触及 |
| 风险 | MySQL 的 3306 端口如果暴露在公网，会被暴力破解 | 即使端口开着，外网也访问不到 |

**原因 2：速度**

| 对比 | 公网通信 | 内网通信 |
|------|---------|---------|
| 延迟 | ~30-50ms（绕一圈互联网） | **~1-5ms**（同机房或同区域） |
| 带宽 | 受限于公网带宽（通常 1-5Mbps） | 内网带宽通常 **1-10Gbps** |
| 稳定性 | 可能丢包、抖动 | 几乎不丢包 |

**原因 3：费用**

| 对比 | 公网通信 | 内网通信 |
|------|---------|---------|
| 流量费 | 腾讯云/阿里云公网流量**按量收费** | 同区域内网流量 **免费** |

### 追问：为什么内网这么快又安全？

> 因为**内网本质上是云厂商机房内部的一根虚拟网线**。

想象一下：

```
公网通信（像寄快递）：
  服务器A → [光缆] → [运营商网络] → [可能经过半个中国] → [光缆] → 服务器B
  ↑ 每一跳都可能被拦截、延迟、收费

内网通信（像办公室里递纸条）：
  服务器A → [云机房内部交换机] → 服务器B
  ↑ 就在同一个机房/同一台交换机上，数据根本不出机房
```

云厂商（腾讯云/阿里云）的所有服务器都接在同一个**虚拟交换机**上，
内网 IP 就是这个交换机分配的地址，数据直接在交换机内部转发。

## 在我们的项目中的具体体现

### 场景：mall-admin 要连接 MySQL

```
┌─────────────────────┐         ┌─────────────────────┐
│  ② 数据服务器        │         │  ② 数据服务器        │
│                     │         │                     │
│  mall-admin :8080   │ ────→   │  MySQL :3306         │
│  (应用容器)          │  内网    │  (数据库容器)         │
│                     │  直连    │                     │
└─────────────────────┘         └─────────────────────┘

连接字符串: jdbc:mysql://mysql:3306/mall
                        ^^^^
                    Docker 内部服务名（也是内网的一种）
```

注意这里有两层"内网"：

### 第一层：Docker 容器之间（同一台机器内）

当 mall-admin 和 MySQL 跑在**同一台服务器**的 Docker 里时：
- 它们通过 Docker 的 **bridge 网络** 通信
- 用**服务名**代替 IP：`mysql:3306`、`redis:6379`
- 这也叫内网，但范围更小（容器级别）

### 第二层：跨服务器之间（不同机器间）

当 Gateway（在 ① 号机）要调用 Admin（在 ② 号机）时：
- 它们不在同一个 Docker 网络里
- 需要用对方的**内网 IP** 或**公网 IP** 来访问

```
┌──────────────────────┐              ┌──────────────────────┐
│ ① 网关服务器          │              │ ② 数据服务器          │
│                      │              │                      │
│ mall-gateway :8201   │──?──────────→│ mall-admin :8080      │
│                      │              │                      │
│ 访问地址写什么？       │              │                      │
└──────────────────────┘              └──────────────────────┘
```

这时候有两种选择：

| 方式 | 写法 | 说明 |
|------|------|------|
| **方式 A：公网 IP** | `http://106.53.132.192:8080` | 能通，但走公网，慢 + 不安全 + 收流量费 |
| **方式 B：内网 IP** | `http://172.x.x.x:8080` | 快 + 安全 + 免费（推荐 ✅） |

## 关键问题：我们的服务器有内网 IP 吗？

### 知识点：云服务器的双网卡

每台云服务器其实有 **两个 IP 地址**：

```
┌─────────────────────────────────┐
│         腾讯云服务器             │
│                                 │
│  ┌──────────┐    ┌──────────┐  │
│  │  公网网卡  │    │  内网网卡  │  │
│  │          │    │          │  │
│  │ 106.53.  │    │ 172.16.  │  │
│  │ 106.41   │    │ x.x.x    │  │
│  │ (对外)    │    │ (对内)    │  │
│  └──────────┘    └──────────┘  │
└─────────────────────────────────┘
```

| IP 类型 | 示例 | 谁能访问 |
|--------|------|---------|
| **公网 IP** | `106.53.106.41` | 全世界任何人 |
| **内网 IP** | `172.16.x.x`（腾讯云）<br>`10.0.x.x` / `192.168.x.x`（阿里云） | 只有**同一地域/同一 VPC 内**的服务器 |

### 怎么查看内网 IP？

```bash
# 登录服务器后执行
ip addr show            # Linux 通用
# 或者
hostname -I             # 显示所有 IP 地址
# 或者（Ubuntu 24.04）
ip -4 addr show eth0    # 查看主网卡
```

### 追问：为什么不能所有通信都用内网 IP？

> **因为用户需要通过公网访问你的系统！**

```
用户浏览器（家里/手机）
    │
    ▼ 公网
106.53.106.41:80  ← Nginx 必须监听在公网 IP 上，否则用户进不来
    │
    ▼ 内网（进入系统之后）
Gateway → Admin → MySQL   ← 这些之间全部走内网
```

所以规则很简单：
- **面向用户的入口**（Nginx）→ 绑定公网 IP
- **服务之间的调用** → 全部走内网 IP

### 一句话总结

> **内网通信 = 服务器之间走云机房内部的专用通道，就像办公室同事之间递纸条，不用寄快递。**
