# Q004：XShell / FinalShell 等工具连接云服务器 — 它们和 SSH 是什么关系？

> **前置阅读**: [003-SSH访问云服务器全流程.md](./003-ssh访问云服务器全流程.md)
> **背景**: 公司里用 XShell 连服务器好像"没有密钥，直接就连上了"，这和命令行 ssh 有什么区别？

---

## 一、结论先行

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│   XShell  =  一个带图形界面的 SSH 客户端              │
│                                                     │
│   命令行 ssh = 手动挡车                              │
│   XShell      = 自动挡车（帮你填好了参数）            │
│                                                     │
│   底层协议完全一样：都是 SSH                          │
│                                                     │
└─────────────────────────────────────────────────────┘
```

**公司里"直接连上去"不是没有认证，而是 XShell 帮你自动完成了认证步骤。**

---

## 二、SSH 客户端的几种形态

| 形态 | 代表 | 使用方式 | 底层协议 |
|------|------|---------|---------|
| **命令行** | `ssh` / PowerShell | 手动敲命令 | SSH |
| **GUI 工具** | XShell / FinalShell / MobaXterm | 图形界面操作 | SSH |
| **IDE 内置** | VS Code Remote-SSH / Trae IDE | 编辑器里直接操作 | SSH |
| **网页版** | 云厂商 VNC 控制台 | 浏览器操作 | **不是 SSH**（是独立协议） |

它们之间的关系：

```
                    SSH 协议（底层）
                   ╱    │    ╲         ╲
                  ╱     │     ╲         ╲
            命令行    GUI工具   IDE内置    VNC(非SSH)
             ssh     XShell   VS Code    浏览器控制台
```

## 三、为什么公司里感觉"没有密钥就直接连了"？

### 场景还原

你在公司打开 XShell 的体验可能是这样的：

```
步骤1: 双击一个会话（比如 "生产服务器-192.168.1.100"）
步骤2: 等待 1~2 秒
步骤3: 直接进入命令行界面 ← 感觉"没输入任何东西就进去了"
```

### 其实背后发生了什么

XShell 的会话配置里**早就存好了所有信息**：

```
┌─────────────────────────────────────────┐
│  XShell 会话配置（你看到的界面）          │
│                                         │
│  主机: 192.168.1.100                    │  ← 对应 HostName
│  端口: 22                               │  ← 对应 Port
│  用户名: root                           │  ← 对应 User
│  认证方式: Password                     │  ← 对应密码认证
│  密码: ******** (已保存)                │  ← 密码被记住了！
│  ┌─────────────────────────┐            │
│  │ ☑ 登录时自动输入密码/密钥 │            │  ← 关键！自动完成认证
│  └─────────────────────────┘            │
│                                         │
│  [确定]                                 │
└─────────────────────────────────────────┘
```

**对比一下等价的手动 ssh 命令**：

```bash
# 如果 XShell 用的是密码认证：
ssh root@192.168.1.100
# → 弹出密码框 → XShell 自动填入保存的密码 → 登录成功

# 如果 XShell 用的是密钥认证：
ssh -i C:\Users\xxx\id_rsa root@192.168.1.100
# → XShell 自动找到私钥文件 → 完成签名 → 登录成功
```

### 一句话解释

> **你感觉"直接连上"，是因为第一次连接时同事已经配好了用户名+密码/密钥，并且勾选了"记住密码"。之后每次双击，XShell 都在后台自动完成了认证过程。**

## 四、XShell 的三种认证方式（对应 SSH 的三种）

### 方式 1：Password（密码）— 最常见于内网环境

```
XShell 配置:
  认证方法: Password
  用户名: root
  密码: Admin@123 (已保存)

连接过程:
  XShell → 输入用户名 root
  服务器 → "请输入密码"
  XShell → 自动填入 Admin@123  ← 你看不到这一步
  服务器 → "欢迎登录 ✅"
```

**为什么公司喜欢用这种方式？**
- 内网服务器不暴露到公网，安全性要求低
- 管理简单：改密码就行，不用管密钥文件
- 团队共享方便：把账号密码发群里大家都能连

**风险**：
- 密码存在 XShell 会话文件里（明文或弱加密）
- 密码可能被泄露（截图、聊天记录）
- 不适合公网服务器（容易被暴力破解）

---

### 方式 2：Public Key（密钥）— 公网服务器推荐

```
XShell 配置:
  认证方法: Public Key
  用户名: root
  密钥: C:\Users\xxx\mykey.ppk  (PuTTY 格式的密钥)

连接过程:
  XShell → 用 mykey.ppk 私钥签名 → 发给服务器
  服务器 → 用 authorized_keys 里的公钥验证 → 匹配 → 登录成功 ✅
```

**注意**: XShell/PuTTY 用的密钥格式是 `.ppk`（PuTTY Private Key），和 OpenSSH 的格式不同！

```
OpenSSH 格式（命令行 ssh 用的）:
-----BEGIN OPENSSH PRIVATE KEY-----
b3BlbnNzaC1rZXktdjEAAAAABG5vbmUAAAA...
-----END OPENSSH PRIVATE KEY-----

PuTTY/XShell 格式（.ppk）:
PuTTY-User-Key-File-2: ssh-rsa
Encryption: none
Comment: imported-openssh-key
Public-Lines: 3
...
Private-Lines: 14
...
Private-MAC: abc123def456
```

两者可以互相转换：
```bash
# OpenSSH → PuTTY (需要 PuTTYgen 工具)
# 打开 PuTTYgen → File → Load private key (选 OpenSSH 的文件) → Save private key (.ppk)

# PuTTY → OpenSSH
puttygen key.ppk -O private-openssh -o id_rsa
```

---

### 方式 3：Keyboard Interactive（键盘交互）— 少见

某些特殊环境（如跳板机、二次验证）使用，会弹出多个交互提示。日常很少用到。

## 五、XShell vs 命令行 ssh — 功能对比

| 能力 | 命令行 `ssh` | XShell |
|------|-------------|--------|
| 远程执行命令 | ✅ `ssh user@host "command"` | ❌ 只能交互式终端 |
| **会话管理** | ❌ 需要自己写 config | ✅ 左侧列表管理多台服务器 |
| **密码记忆** | ❌ 每次手动输（除非用 sshpass） | ✅ 可保存密码/密钥 |
| **SFTP 文件传输** | 需另开 `sftp` / `scp` | ✅ 内置 SFTP 标签页，拖拽上传下载 |
| **脚本自动化** | ✅ 天然支持（可写在 shell 脚本里） | ⚠️ 支持 VB/JS 脚本但较复杂 |
| **隧道/端口转发** | `-L` / `-R` / `-D` 参数 | ✅ 图形化配置 |
| **外观美化** | 纯黑白终端 | ✅ 字体/主题/配色/标签页 |
| **ZModem 传输** | ❌ | ✅ rz/sz 直接传文件 |

### 各自适用场景

```
命令行 ssh 更适合:
  ✅ 写脚本批量操作多台服务器
  ✅ 在 IDE（Trae/VS Code）里开发时远程调试
  ✅ DevOps / 运维自动化场景

XShell 更适合:
  ✅ 日常手动运维管理
  ✅ 需要频繁上传下载文件
  ✅ 同时管理几十台服务器（会话列表一目了然）
  ✅ 新手入门（图形界面友好）
```

## 六、FinalShell — 国产替代品

国内也常用 **FinalShell**（开源免费），功能和 XShell 类似但有一些特色：

| 特性 | 说明 |
|------|------|
| **国产免费** | 不用担心版权问题（XShell 商业版收费） |
| **自带监控面板** | CPU/内存/网络/磁盘实时图表（这个很实用） |
| **同步目录** | 本地和远程目录双向同步 |
| **云主机管理** | 可以导入腾讯云/阿里云的实例列表 |

FinalShell 底层也是 SSH，认证方式和 XShell 完全一样。

## 七、回到我们的项目：三种连接方式都可以用

我们的 3 台服务器可以用任何一种方式连接：

```bash
# 方式1: Trae IDE 终端（命令行 ssh + config 别名）
ssh tengxun-server9        # 最快，已经在 config 里配好了

# 方式2: XShell / FinalShell（GUI）
# 新建会话 → 填入:
#   主机: 106.53.132.192
#   端口: 22
#   用户: root
#   认证: Public Key → 选择 tengxun_server9.pem
#   ☑ 记住密码/密钥
# → 双击即可连接

# 方式3: VS Code Remote-SSH
# 安装 "Remote - SSH" 扩展
# F1 → "Remote-SSH: Connect to Host" → Configure SSH Hosts
# 填入: root@106.53.132.192
# 选择密钥文件路径 → 连接
```

**推荐组合**：

```
日常快速操作 → Trae IDE 终端（ssh 别名，秒连）
需要传文件   → FinalShell / XShell（SFTP 拖拽方便）
写脚本批量跑 → 命令行 ssh（天然支持循环/并行）
```

## 八、为什么云厂商强制推荐密钥而不是密码？

你可能注意到：

| 云厂商 | 新购服务器默认认证方式 |
|--------|-------------------|
| **腾讯云** | 强制密钥（PEM 文件下载）|
| **阿里云** | 可选密钥或密码 |
| **AWS** | 强制密钥（PEM 文件下载）|

### 知识点：为什么腾讯云/AWS 强制密钥？

**是什么？**
新购服务器时，你必须先创建或上传一个密钥对，然后下载私钥（`.pem`），**之后只能通过这个私钥登录**，不能设密码。

**为什么？**

```
公网服务器的现实:

  你的服务器 IP: 106.53.132.192
       ↑
       │ 全世界任何人都能看到这个地址
       │
       ▼
  ┌──────────────────────────────────┐
  │  互联网上的扫描机器人（每秒数万次） │
  │                                  │
  │  "发现一台新服务器！              │
  │   端口 22 开着...                 │
  │   开始暴力猜密码:                 │
  │   admin/admin, root/root,        │
  │   root/123456, root/password..." │
  │                                  │
  └──────────────────────────────────┘

如果用密码认证:
  → 弱密码 → 几分钟就被破解 → 服务器变肉鸡 😱

如果用密钥认证:
  → 即使端口开着，没有私钥谁也登不进来 ✅
  → 私钥只在你电脑上，不在网络上传输
```

**追问：那公司内网为什么敢用密码？**

> 因为内网服务器**没有公网 IP**，外网根本访问不到。
> 只有公司内网 / VPN 里的人才能尝试连接，
> 攻击面极小，所以密码认证的风险可控。

---

## 一句话总结

> **XShell 就是 SSH 的"自动挡版"——它帮你记住了 IP、用户名、密码/密钥，所以你觉得"直接就连上了"。底层完全一样，换汤不换药。**
>
> **公网服务器用密钥（安全），内网服务器用密码（省事）。**
